# Thesis Research Assistant

A small self-hosted tool that speeds up academic reading and note-taking for
a thesis/dissertation literature review. Pull a source from **Zotero**,
**upload a PDF**, or **paste a link**, then generate cited notes using five
reading/writing methodologies, all grounded in the actual source text with
page citations.

## Methodologies

- **Rhetorical Precis** — the classic four-sentence Woodworth structure
  (thesis, development, purpose, audience).
- **Dialectical Notetaking** — a double-entry table of key quotes/paraphrases
  (with page numbers) paired with your reader response, plus a synthesis.
- **Charted Reading** — a structured "reading chart" (thesis, methodology,
  findings, evidence, strengths/limitations, notable quotes) shaped so rows
  from multiple sources can be stacked into a synthesis matrix later.
- **Concept Development** — a Walker & Avant–style concept analysis of a term
  or phrase you specify: uses/classifications, defining (critical)
  attributes, a model ("live") case, a contrary ("dead") case, antecedents,
  consequences, and empirical referents.
- **Key Term Comparison** — a comparison/contrast table across two or more
  terms, plus an analogy that captures how they relate.

Every generated note cites the source (author/year/page) and is exported as
clean Markdown; the app never invents quotations that aren't in the text.

## How it works

- **FastAPI backend** (`backend/`) handles ingestion (Zotero API via
  `pyzotero`, PDF text extraction via `pypdf`, web page extraction via
  `requests` + `BeautifulSoup`) and calls the Claude API (`anthropic` SDK)
  with methodology-specific prompts.
- **Plain HTML/JS frontend** (`frontend/`) — no build step, served directly
  by FastAPI.
- Ingested source text is kept **in memory only** (not written to disk, not
  persisted across restarts) — this is a single-user, single-process tool.
- Your **Zotero API key** is entered in the browser, stored only in
  `localStorage`, and sent straight to your own server per-request; it is
  never written to disk server-side. Your **Anthropic API key** lives in the
  server's `.env` file since every user of this instance shares one Claude
  account.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# edit .env and set ANTHROPIC_API_KEY

uvicorn backend.main:app --reload --port 8000
```

Open http://localhost:8000

## Using it

1. **Add a source**
   - *Zotero tab*: paste your [Zotero API key](https://www.zotero.org/settings/keys)
     and library ID (your numeric user ID for a personal library, or the
     group ID for a group library), then "Load Items" and click one. The app
     downloads its first PDF attachment and extracts the text (falls back to
     the abstract if no PDF is attached).
   - *Upload PDF tab*: upload any PDF directly; optionally fill in citation
     fields (auto-detected from PDF metadata otherwise, which is often
     unreliable — worth checking).
   - *Paste Link tab*: paste a URL; the app extracts the main article text
     and tries to sniff a title/author/date from the page's meta tags.
2. **Choose analyses** — tick the methodologies you want. Concept Development
   needs a term/phrase; Key Term Comparison needs two or more comma-separated
   terms.
3. **Run Analysis** — each selected methodology is generated by Claude,
   grounded in the extracted text, with page citations.
4. **Export** — copy or download each note as Markdown, export everything at
   once, or (if the source came from Zotero) save the notes back to that
   Zotero item as child notes.

## Notes & limitations

- PDF extraction only pulls text layers — scanned/image-only PDFs need OCR
  first (not included here).
- Very long sources are truncated to `MAX_SOURCE_CHARS` (default ~180k
  characters) to stay within the model's context window.
- The APA-style reference string is auto-generated from available metadata
  and is a convenience, not a citeproc-accurate bibliography — verify before
  it goes in a final bibliography.
- This is intentionally a single-process, in-memory tool for one researcher
  running it locally; there's no database, auth, or multi-user support.
